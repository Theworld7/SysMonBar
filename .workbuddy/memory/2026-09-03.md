## AI 配置总控与状态栏显隐联动（SysMonBarApp.swift）
- 需求：AI 配置面板开关 = 总控权限，优先级高于设置中 AI 状态栏显隐；总控关闭时设置 Toggle 置禁用、值保留但失效；设置中 AI 厂商显隐仅控制状态栏 label。
- 根因：原 `AIProviderConfigView.apply()` 直接写 `settings.showDeepSeek/showMiniMax`，与设置共用同一存储字段，互相覆盖。
- 方案（用户拍板：保留但失效 + AI 区整体隐藏）：
  - `StatusBarSettings` 新增总控 `deepSeekEnabled`/`miniMaxEnabled`（key `ai.deepseek_enabled`/`ai.minimax_enabled`，默认 true）+ 派生属性 `statusBarShowsDeepSeek/MiniMax`（总控 && 设置）、`aiPanelVisible`（任一总控开）。
  - `MenuContentView` AI 区改由 `aiPanelVisible`/`deepSeekEnabled`/`miniMaxEnabled` 控制，两厂商全关时 Divider+section+按钮整体隐藏。
  - `SettingsView` Toggle 加 `.disabled(!总控)`。
  - `StatusBarLabel` 改用派生属性。
  - `AIProviderConfigView` init 回填与 `apply()` 均改为读写总控字段。
- 编译：xcodebuild 需 `-derivedDataPath` 指到项目内 build/（沙箱拦 DerivedData 写入，`build.sh` 本身就用 `-derivedDataPath build`）；BUILD SUCCEEDED（deployment target 27.0 警告为既有问题）。
- 后续补齐（两次"继续"）：
  - 设置页 Section footer 说明总控联动；`Section("状态栏显示项")` 改为 `Section { ... } footer:`。
  - 总控关闭联动轮询启停：`AppState.init` 移除 `quotas.start()`，AppDelegate 中订阅 `settings.$deepSeekEnabled.combineLatest($miniMaxEnabled)`（@Published 在值变化后发射，订阅时立即发射当前值）驱动 provider start/stop，总控关 = 停止 5min 轮询。
  - 弹窗"刷新"按钮只刷新总控启用的厂商；删除因此孤立的 `QuotaCoordinator.refreshAll()`。
  - safe-delete shim 拦截大批量 `rm -rf`（2246 文件 >50 阈值），build/DerivedData 临时产物保留未清。
  - 冒烟验证：Debug 构建 open 启动 3s 存活（新 settings 初始化 + Combine 订阅无崩溃）；osascript quit 被沙箱拦（-10004），`kill -TERM` 可优雅退出（applicationWillTerminate 正常执行）；IDEA.md 仅一行构想无需同步文档。

## 面板焦点修复（SysMonBarApp.swift togglePopover）
- 问题：NSPopover 内容窗口是 nonactivating panel，点状态栏时应用未激活，弹窗无法成为 key window，需额外点击才能交互。
- 修复（togglePopover 展开分支，3 行）：`NSApp.activate(ignoringOtherApps: true)` → `pop.show(...)` → `pop.contentViewController?.view.window?.makeKey()`。关闭路径不动（transient popover 关闭时系统自动交出 key status）。
- 一致性：仅 togglePopover 一处调用 show，每次展开都走 activate+makeKey，连续开合行为一致；面板内部控件焦点仍由 SwiftUI 自行接管。
- 验证：BUILD SUCCEEDED；键盘聚焦行为需人工验证（沙箱无法模拟状态栏点击），用户在 Xcode 重跑后点击图标检查。
- 经验：`lsappinfo info -app <pid>` 可查进程来源（父 ASN/Xcode、bundle path、launch time），ps 被沙箱禁时的替代方案。
